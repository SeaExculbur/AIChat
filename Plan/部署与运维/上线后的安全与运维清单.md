# 上线后的安全与运维清单

> 网站能访问只是开始。本文是上线后的检查清单：攻击面、密钥、备份、监控、证书、日常操作。

---

## 一、先画清攻击面

```
公网
 │
 ├─ 22/tcp   SSH（只认密钥）
 ├─ 80/tcp   nginx：ACME 验证 + 301
 └─ 443/tcp  nginx：静态页面 + /api/ 反代
                │
                └─ 容器网络（不对外）
                     ├─ flask:5000
                     └─ postgres:5432
```

**关键**：Postgres 和 Flask 都没有发布到宿主机端口，公网无法直接访问。只有 nginx 有公网入口。

## 二、安全组

| 端口 | 来源 | 建议 |
|---|---|---|
| 22 | `0.0.0.0/0` | 尽量改成你家/学校的公网 IP；至少确认已关闭密码登录 |
| 80 | `0.0.0.0/0` | 必须开，ACME 续期和 HTTP 跳转用 |
| 443 | `0.0.0.0/0` | 必须开 |
| 其他 | — | 一律不开；数据库、Flask 不要发布端口 |

检查服务器本机监听：

```bash
ss -tlnp
```

期望只看到 22、80、443（以及 Docker 的内部端口）。

## 三、SSH

### 3.1 已经做的

- 只认密钥，`PasswordAuthentication no`
- 私钥在本地 `C:\Users\123\.ssh\_aichat-server.pem`
- `ServerAliveInterval 30` 防止空闲断连

### 3.2 建议再做的

1. **收窄 22 的来源 IP**：安全组里把 `0.0.0.0/0` 改成你的固定公网 IP
2. **禁用 root 直接登录**（可选）：新建普通用户 + `sudo`，`PermitRootLogin no`
3. **定期轮换密钥**：怀疑泄露时，删掉服务器 `~/.ssh/authorized_keys` 里的旧公钥

## 四、密钥与配置

### 4.1 已经在做的

| 项 | 状态 |
|---|---|
| `.env.production` 不入库 | ✅ `.gitignore` |
| `.env.production` 不进镜像 | ✅ `backend/.dockerignore` 里的 `.env*` |
| 文件权限 | ✅ `chmod 600` |
| 代码仓库里没有 DeepSeek Key / JWT Secret | ✅ |

### 4.2 还需要注意的

**数据库密码**：

`docker-compose.yml` 里的 `POSTGRES_PASSWORD` 目前是明文，而且这个文件在 Git 里。虽然 Postgres 没有对公网暴露，风险有限，但更好的做法是：

```yaml
environment:
  POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
```

然后在 `.env.production` 里放密码（compose 会自动读取同目录的 `.env`，或显式 `env_file`）。注意：`POSTGRES_PASSWORD` 只在**数据库首次初始化**时生效；已有数据卷时改环境变量不会改数据库里的密码，需要进容器执行：

```sql
ALTER USER aichat WITH PASSWORD '新密码';
```

同时更新 `DATABASE_URL`。

**JWT 密钥**：`JWT_SECRET_KEY` 泄露 = 别人可以伪造任意用户的 token。不要提交、不要贴到聊天/issue。

**DeepSeek Key**：泄露会被盗用产生费用。建议在 DeepSeek 控制台设置额度上限。

## 五、TLS 证书

| 项 | 状态 |
|---|---|
| 证书有效期 | 90 天，自动续期 |
| 续期定时器 | `certbot.timer` |
| 续期后 reload nginx | `renewal-hooks/deploy/reload-nginx.sh` ✅ |
| 只启用 TLS 1.2/1.3 | ✅ |
| 私钥权限 | `600`，root only |

### 5.1 定期检查

```bash
systemctl list-timers | grep certbot
sudo certbot certificates
```

`certbot certificates` 会显示每张证书的到期时间和路径。

### 5.2 HSTS（可选，稳定后再加）

```nginx
add_header Strict-Transport-Security "max-age=31536000" always;
```

作用：告诉浏览器"以后这个域名只用 HTTPS 访问"。
风险：配置错了回退麻烦（浏览器会缓存），所以先确认 HTTPS 长期稳定。

## 六、备份

### 6.1 现在数据在哪

- Postgres 数据：宿主机 `/root/AIChat/pgdata`（bind mount）
- 证书：`/etc/letsencrypt`
- 代码：Git + 服务器 `/root/AIChat`

### 6.2 bind mount 不等于备份

`pgdata` 只保证"容器删了数据还在"，解决不了：

- 磁盘损坏
- 误删
- 勒索软件
- 云服务器实例被释放

### 6.3 建议：逻辑备份 + 异地

```bash
mkdir -p /root/backup

# 手动备份
docker compose -f /root/AIChat/docker-compose.yml exec -T db \
  pg_dump -U aichat -d aichat | gzip > /root/backup/aichat-$(date +%F).sql.gz
```

crontab（每天 3 点）：

```cron
0 3 * * * cd /root/AIChat && docker compose exec -T db pg_dump -U aichat -d aichat | gzip > /root/backup/aichat-$(date +\%F).sql.gz
```

保留 7 天：

```cron
0 4 * * * find /root/backup -name 'aichat-*.sql.gz' -mtime +7 -delete
```

**必须验证恢复**：定期把备份导入一个临时库，确认能读出来。没验证过的备份等于没有。

## 七、监控与日常巡检

### 7.1 每天/每周看一眼

```bash
# 容器状态
cd /root/AIChat && docker compose ps

# 最近日志
docker compose logs --tail=50 flask
docker compose logs --tail=50 nginx

# 磁盘
df -h /

# 内存 / swap
free -h

# 证书到期
sudo certbot certificates
```

### 7.2 关键指标

| 指标 | 阈值 | 处理 |
|---|---|---|
| 磁盘使用率 | > 80% | 清理日志/备份，扩容 |
| 内存 | 持续 > 90% | 检查进程，考虑升配 |
| swap 使用 | 持续增长 | 内存不足，排查泄漏或升配 |
| 容器重启次数 | 频繁 | `docker inspect --format '{{.RestartCount}}'` |
| 证书剩余天数 | < 30 天 | 检查续期任务 |

### 7.3 外部可用性

可以用免费的 uptime 监控（如 UptimeRobot）定时请求 `https://你的域名`，挂了发邮件。自建的话也可以用 cron + curl + 邮件。

## 八、镜像与依赖

### 8.1 钉住基础镜像版本

现在 Dockerfile 用的是浮动 tag：

```dockerfile
FROM python:3.13-slim
FROM node:22-alpine
FROM nginx:alpine
```

建议改成精确版本或 digest：

```dockerfile
FROM python:3.13.7-slim
FROM node:22.20-alpine
FROM nginx:1.31.8-alpine
```

或者用 digest：

```dockerfile
FROM nginx@sha256:060849a174666c...
```

**为什么**：浮动 tag 会在某次重建时悄悄换版本，可能引入不兼容或行为变化。这相当于 Docker 世界的 lockfile。

### 8.2 依赖更新

- Python：`pip list --outdated`，或 `pip-audit` 查漏洞
- 前端：`npm outdated`、`npm audit`
- 更新后：重建镜像 → `docker compose up -d --no-deps 服务` → 回归测试

## 十、故障排查速查

| 现象 | 先查什么 | 常见原因 |
|---|---|---|
| 整站打不开 | `docker compose ps`、安全组、DNS | 容器挂了 / 安全组改了 / DNS 过期 |
| 502 Bad Gateway | `docker compose ps flask`、`logs flask` | Flask 没起来 / 崩溃 / 端口不对 |
| 500 | `docker compose logs flask` | 代码异常 / 数据库连不上 |
| 页面能开但接口 401 | 浏览器 localStorage 里的 token | 过期（2 小时）/ 没登录 |
| 页面能开但接口 403 | 用户 `is_active` | 未放行 |
| 登录后马上又回登录页 | token 是否过期、JWT 密钥是否变过 | 密钥变更导致旧 token 失效 |
| 流式输出截断 | nginx `proxy_read_timeout`、gunicorn `timeout` | 超时太短 |
| 证书过期 | `sudo certbot certificates` | 续期失败 / 钩子没 reload |
| 磁盘满 | `df -h`、`docker system df` | 日志/镜像/备份堆积 |
| 数据库连不上 | `docker compose exec db pg_isready` | 容器没起 / 密码错 / 卷权限 |

## 十二、成本与容量

当前配置：2 核 1.7G 内存 + 2G swap，40G 磁盘。

| 资源 | 现状 | 观察点 |
|---|---|---|
| 内存 | 1.7G，加 2G swap | Gunicorn 4 worker + Postgres + nginx 够用；构建时会吃紧 |
| 磁盘 | 40G，已用少量 | 镜像、日志、备份会增长 |
| 带宽 | 按阿里云套餐 | SSE 是长连接，注意并发和流量 |

**Gunicorn `workers = 4`**：每个 SSE 长连接会占住一个 sync worker。4 个并发聊天就会把 worker 占满，第 5 个请求要等。自用够；多人用要考虑 `gthread` / `gevent` worker 或异步方案。
