# 域名、备案与 DNS 解析实战

> 本文解决三个问题：域名怎么指向服务器、备案到底管什么、解析生效前后怎么验证。

---

## 一、先把概念分清

| 概念 | 一句话解释 | 类比 |
|---|---|---|
| **域名** | 给人看的地址，如 `seaexculbur.com` | 公司名字 |
| **DNS** | 把域名翻译成 IP 的系统 | 电话簿 |
| **A 记录** | "域名 → IPv4 地址"的一条映射 | 电话簿里的一行 |
| **TTL** | 这条记录在各地 DNS 缓存里能存多久（秒） | 电话簿多久更新一次 |
| **ICP 备案** | 中国大陆对网站主办者的资质登记 | 营业执照 |
| **安全组** | 云服务器的虚拟防火墙 | 大楼门禁 |

**关键区分**：备案和解析是两件独立的事。

- 备案解决"你有没有资格在大陆服务器上开网站"
- 解析解决"域名指向哪台机器"
- 安全组解决"哪些端口能从公网进来"

三者都通了，浏览器才能访问到你的页面。

---

## 二、ICP 备案：为什么必须有

在中国大陆的服务器上提供网站服务，域名必须先完成 **ICP 备案**（工信部备案）。没有备案的域名解析到大陆服务器，访问会被拦截。

备案的几个要点：

1. **备案主体**：个人或企业。个人备案需要身份证、手机号等。
2. **备案域名**：备案的是具体域名，不是服务器。换服务器不用重新备案，但换域名要。
3. **备案号**：通过后会拿到一个类似 `京ICP备xxxxxxxx号` 的编号。
4. **展示义务**：网站底部必须展示备案号，并链接到 `https://beian.miit.gov.cn`。

### 公安联网备案

ICP 备案通过后，**网站上线 30 日内**还要做**公安联网备案**（在"全国互联网安全管理服务平台"）。这一步很容易漏，但不做属于违规。

### 备案不是"域名注册"

域名注册是买下这个域名的使用权；备案是向工信部登记"这个域名要用来开网站"。两件事在不同平台、不同流程。

## 三、添加 DNS 解析

以阿里云云解析为例（其他服务商界面不同，概念一样）：

1. 进入 **云解析 DNS → 域名解析 → 解析设置**
2. 添加两条 A 记录：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | 服务器公网 IP | 600 |
| A | `www` | 服务器公网 IP | 600 |

### `@` 和 `www` 分别是什么

- `@` 代表**根域名**本身，即 `seaexculbur.com`
- `www` 代表 `www.seaexculbur.com`
- 只加 `@` 的话，用户输入 `www.域名` 会打不开；两条都加最省心

### TTL 怎么选

- 首次配置建议 **600 秒（10 分钟）**，方便改错后快速生效
- 稳定后可以调到 3600 秒，减少 DNS 查询压力
- TTL 只是"缓存多久"，不代表"必须等这么久才生效"

### 公网 IP 从哪里看

- 阿里云 ECS 控制台实例列表的"公网 IP"
- 或在服务器上执行 `curl -s ifconfig.me`

**不要用 `hostname -I`**，那通常是内网 IP（`172.x` / `10.x`），域名指过去没有用。

## 四、验证解析是否生效

### 本机验证

```bash
nslookup seaexculbur.com 223.5.5.5
nslookup www.seaexculbur.com 223.5.5.5
```

或者：

```bash
dig @223.5.5.5 seaexculbur.com +short
```

期望返回服务器的公网 IP。

**为什么要指定 `223.5.5.5`**：这是阿里公共 DNS。不指定的话，查询会走你本地运营商或路由器的缓存，可能看到旧结果。指定公共 DNS 能更快看到权威结果。

### 浏览器验证

```text
http://seaexculbur.com
```

能打开页面，说明"域名 → DNS → 公网 IP → 安全组 80 → nginx"整条链路通了。

## 五、安全组和 DNS 是两层

一个请求到达服务器，要过两关：

```
浏览器
  │  DNS 解析：域名 → 120.x.x.x
  ▼
公网 IP:80
  │  安全组：是否允许 TCP 80 进入？
  ▼
服务器
  │  主机防火墙（ufw/iptables）：本机默认 inactive
  ▼
nginx 是否在 80 上监听？
```

- DNS 配对了，但安全组没开 80 → 连接超时
- 安全组开了，但 nginx 没监听 → 连接被拒绝
- 两者都通，nginx 配置错 → 404 / 502 / 301 循环

排查时按这个顺序一层层看，不要一上来就改配置。

## 六、常见坑

### 1. 只加了 `@`，没加 `www`

现象：`seaexculbur.com` 能开，`www.seaexculbur.com` 打不开。
原因：这是两条独立记录。
解决：补一条 `www` 的 A 记录。

### 2. 用了"URL 转发"而不是 A 记录

阿里云有"显性 URL / 隐性 URL"记录，那是在 DNS 层做跳转，不是把域名解析到你的服务器。
表现：地址栏可能变成别的域名，或者根本到不了你的 nginx。
解决：用 A 记录。

### 3. 开了 Cloudflare 的橙色云朵

橙色云朵表示"代理模式"，DNS 返回的是 Cloudflare 的 IP，你的服务器看到的是 Cloudflare 的 IP。
对配 HTTPS 来说会增加复杂度（证书要配在 Cloudflare 或源站，还要处理 `X-Forwarded-For`）。
自用项目建议先用"仅 DNS"（灰色云朵）。

### 4. 解析改了但本机还是旧结果

DNS 缓存。用 `nslookup 域名 223.5.5.5` 绕开本地缓存；或者等 TTL 到期。

### 5. 备案域名和解析域名不一致

备案的是 A 域名，却把 B 域名解析到大陆服务器 → B 会被拦截。
解决：备案哪个用哪个。

## 七、本次实际步骤回顾

1. 确认域名已备案
2. 拿到服务器公网 IP
3. 阿里云云解析 → 快速添加解析 → 勾选 `@` 和 `www` → 填公网 IP
4. `nslookup` 两条都返回正确 IP
5. 安全组放行 80 / 443
6. `http://域名` 返回 200
7. 之后再做 HTTPS（见《HTTPS证书与TLS握手.md》）

---

## 八、一句话总结

**备案是资质，解析是地址，安全组是门禁。** 浏览器能访问，说明这三层加上 nginx 监听全都对了；任何一层不对，表现各不相同，排查时先定位是哪一层。
