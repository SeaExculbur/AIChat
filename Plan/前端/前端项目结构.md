# 前端项目结构——每个文件夹为什么存在

> 项目：AIChat v1.0  
> 目的：理解前端架构的文件夹分工——为什么不能全写在一个文件里  

---

## 一、核心问题：为什么不能全写在 `App.vue` 里

你后端拆了 `auth.py`、`chat.py`、`models.py`——但不是 Python 不让你放一个文件里。前端同样——Vue 允许一个 `.vue` 文件里的 `<template>` 塞整个网站，但项目一大就崩。

拆文件夹解决三个问题：

| 问题 | 不拆会怎么样 | 拆了后 |
|------|------------|--------|
| 一个人找代码 | 登录页逻辑混在聊天页样式旁边——改一行翻几百行 | 打开 `views/Login.vue`——整个登录页就这一个文件 |
| 多人并行开发 | 你改路由、室友改状态——同一文件 Git 合并冲突 | 你改 `router/`、室友改 `store/`——互不冲突 |
| 代码复用 | 登录和注册的输入框样式复制两遍——改一处漏一处 | 抽出一个公共组件放在 `components/`——两页引用同一个 |

你后端蓝图的本质是把路由按功能拆分。前端做同样的事——只是拆的不只是路由，还有状态、API 封装、可复用 UI 组件。

---

## 二、每个文件夹做什么

```
src/
├── main.js                ← 入口——创建 Vue 应用、注册插件、挂载
├── App.vue                ← 根组件——所有页面的外层壳（<router-view />）
│
├── router/                ← URL → 页面组件的映射表
│   └── index.js
│
├── views/                 ← 页面——每个 URL 对应一个
│   ├── Login.vue
│   ├── Register.vue
│   └── Chat.vue
│
├── components/            ← 可复用组件——被多个页面共享
│   └── MessageBubble.vue  （聊天消息的气泡，以后可能抽出来）
│
├── store/                 ← 全局状态——多个页面都要读写的数据
│   └── auth.js            （token、当前用户信息）
│
├── api/                   ← HTTP 请求封装——和后端通信的入口
│   └── request.js         （Axios 实例、拦截器）
│
├── assets/                ← 静态资源——图片、字体、全局 CSS
│
└── public/                ← 不编译的静态文件——图标、robots.txt
    └── favicon.svg
```

---

## 三、文件夹之间的数据流

```
用户操作 Login.vue
  → 调 api/request.js 里的 axios 实例（自动加 token）
  → 后端返回 token
  → 存入 store/auth.js（Pinia store）
  → router/index.js 路由跳转
  → Chat.vue 渲染
```

每条路径是单向的：`views` → `api` → 后端；`views` → `store` → 其他 `views` 读。不回头 import。

这个 import 方向和你后端的 `app → auth → models`（不回头）是同一条规则。

---

## 四、与后端的精确类比

| 前端文件夹 | 干什么 | 后端等价 |
|-----------|--------|---------|
| `router/index.js` | URL → 页面的映射表 | `app.register_blueprint(auth_bp)` |
| `views/*.vue` | 每个 URL 对应的页面 | `auth.py` 里的 `login()`、`register()` 函数 |
| `components/` | 多个页面复用的 UI 零件 | 被抽取到 `utils.py` 里的公共函数 |
| `store/` | 跨页面共享的数据（token、用户信息） | `threading.local`——同一请求上下文里的共享存储 |
| `api/request.js` | HTTP 请求配置（baseURL、拦截器、超时） | `requests.Session()` + 自定义 header |
| `main.js` | 创建 Vue 应用、注册插件、启动 | `app.py` 里的 `create_app()` |
| `App.vue` | 所有页面的外层壳 | 没有精确对应——可类比 `base.html` 外层模板 |
| `assets/` | 图片和全局 CSS | 无代码对应——纯资源 |
| `public/` | 不编译的静态文件 | `static/` 目录 |

---

## 五、最小项目可以少到几个文件

你如果只做一个小工具——一个文件 `App.vue` 够了。文件夹是跟着复杂度长的。为什么你项目里现在有这么多文件夹？因为你前端有：路由、状态管理、API 封装、多页面——每一项复杂到一个 `.vue` 文件装不下的时候，自然需要一个独立的文件夹。

你后端也不是一开始就拆 `auth.py` 和 `chat.py`——你先把所有路由写在一个 `app.py` 里，多到翻不动了自然拆。前端同理。
