## 一、HTTP 报文在源码层面如何组装

### 当前认知

你知道 axios 和 fetch 把 JS 对象转成 HTTP 报文发给后端。但不知道**具体哪行代码拼出了 `POST /api/chat HTTP/1.1`**。

### 待拆

- axios 源码里从 `axios.post(url, body)` 到 `fetch(url, { method, headers, body })` 的调用链
- fetch 的 JS 入口 → 浏览器 C++ 层的边界在哪个函数
- HTTP 请求行、请求头、请求体的字节数组是在 C++ 堆上拼接的还是在 JS 层完成的
- `Content-Type: application/json` 和 `Authorization: Bearer xxx` 在字节数组里长什么样

## 二、浏览器 C++ 网络栈——fetch 之下的世界

### 当前认知

你知道 "fetch → C++ 网络栈 → 操作系统 socket API → TCP 握手" 这个链路。但不知道 C++ 层具体做了什么。

### 待拆

- 浏览器 C++ 网络栈的模块结构（Chromium 的 `//net` 目录）
- `TCPSocket::Connect()` 和 `StreamSocket::Read()` 在源码级的位置
- HTTP 报文解析器——C++ 层怎么把字节流拆成状态行、响应头、响应体
- 为什么 C++ 层的网络操作不阻塞 JS 主线程——libevent / epoll 在浏览器里的运用
- 浏览器怎么管理 TCP 连接池（同一个域名复用连接，还是每次新开）

### 和你的 socket 代码的关系

你去年写的 `s.connect()` + `s.send()` + `s.recv()`——浏览器 C++ 网络栈做的事和它完全一样，只是包了一层 HTTP 协议解析和连接池管理。

## 三、JS 引擎（V8）——JS 代码怎么变成机器码

### 当前认知

你知道 "V8 执行 JS 源码"。但不知道它内部的编译和执行机制。

### 待拆

- V8 的 JIT 编译管线：Ignition（解释器）→ TurboFan（优化编译器）
- JS 源码 → AST（抽象语法树）→ 字节码 → 机器码 的完整转换链路
- 单线程模型——V8 为什么只有一个调用栈，这个调用栈在 C++ 里是怎么实现的
- 垃圾回收（GC）——新生代和老年代的回收策略（Scavenge / Mark-Sweep）
- 事件循环的 C++ 实现——`libuv` 在 Node.js 里，浏览器里是 Chromium 的消息循环

### 和你的 C 语言知识的关系

C 写的 `gcc -S` 生成汇编——V8 的 TurboFan 也是在内存里生成机器码，只是不写磁盘。你可以从你熟悉的 C 编译链去理解这个 JIT 分支。

## 四、Vue 编译器——.vue 文件变成了什么

### 当前认知

你知道 `.vue` 三段（`<script>`、`<template>`、`<style>`）被编译成浏览器能跑的 HTML + JS + CSS。

### 待拆

- `<template>` 里的 `v-model`、`v-for`、`{{ }}` 被编译成什么 JS 代码
- 编译产物里 `render()` 函数长什么样——如何通过 `h('div', { class: 'user-bubble' }, '你好')` 生成虚拟 DOM
- `<style scoped>` 如何实现组件级样式隔离——Vue 给每个元素加了什么属性
- `@click`、`@keydown` 编译后落在哪个 JS API 上（`addEventListener` 还是其他）
- SFC 编译器（`@vue/compiler-sfc`）的工作流程：parse → transform → generate
- 你 `Login.vue` 的编译产物长什么样——用 `vue/compiler-sfc` 打开一个 `.vue` 文件看输出

### 和后端的类比

Flask 的 `@app.route` 被装饰器语法糖包裹——你拆过底层是 `add_url_rule`。Vue 的 `@click` 被编译器语法糖包裹——底层是 `addEventListener`。同一条路：语法糖拆到底层 API。

## 五、浏览器渲染管线——CSS 怎么变成像素

### 当前认知

你知道 CSS 属性改变样式，但不知道浏览器怎么把 CSS 文本变成屏幕上的像素。

### 待拆

- 渲染管线的五步：HTML → DOM 树 → CSSOM 树 → Render Tree → Layout（布局）→ Paint（绘制）→ Composite（合成）
- `display: flex` 在 Layout 阶段怎么算每个元素的位置——和 `margin-left: auto` 在源码级怎么被归结为矩形坐标
- GPU 合成——`animation` 为什么比 `left: 100px` 动画流畅
- 重排（reflow）和重绘（repaint）的区别——改哪个属性能绕过哪几步

### 是什么

Pinia 是 Vue 3 官方推荐的状态管理库——一个全局共享的响应式对象。等价于你后端的 `threading.local`——多个组件都能读写同一份数据。

### 待拆

- 为什么不能只用 `ref` 解决全局状态——`ref` 在单个组件内，跨组件传数据靠 props（层层传）或 provide/inject
- Pinia store 创建的时机——在 `app.use(pinia)` 之后，一个 store 的生命周期
- Pinia 和 localStorage 配合——页面刷新后从 localStorage 恢复 token，重新写入 Pinia

## 八、SSE 与 WebSocket 的源码级差异

### 当前认知

你知道 SSE 是单向流（后端推、前端收），WebSocket 是全双工。但没拆过它们在浏览器 C++ 层的实现差异。

### 待拆

- SSE 的底层——同一个 HTTP 连接上浏览器 C++ 层持续 recv，不解开 TCP
- WebSocket 的底层——HTTP 升级握手后 TCP 管道转为 WebSocket 帧协议
- 为什么 chat 场景 SSE 够用——前端永远先发请求，不存在后端主动推的场景
- EventSource API（SSE 的另一种写法）和 fetch + ReadableStream 的区别
