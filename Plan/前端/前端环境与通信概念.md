> 项目：AIChat v1.0  
> 日期：2026-06-19  
> 内容：前端环境搭建涉及的工程工具、通信协议、架构概念  

---

## 一、项目骨架与工程结构

### 脚手架（Scaffold）

`npm create vite@latest frontend -- --template vue` 做的事情：把一整套互相关联的初始文件复制到 `frontend/` 目录。

**为什么需要**：后端文件少（7 个），可以手动建。前端一个 Vue 3 项目起步就要十几个文件（`package.json`、`vite.config.js`、`index.html`、`main.js`、`App.vue`……），它们之间有精确的引用关系，少一个或引错一个 → 页面空白但无报错。

**类比**：`db.create_all()`——都是"第一次建表/建目录"的自动化操作。之后每改一个文件都是在骨架上追加自己的代码，脚手架不会再碰。

### package.json

前端版 `requirements.txt`，但多一个 `"scripts"` 字段：

```json
"scripts": {
    "dev": "vite",          // npm run dev → 实际执行 vite
    "build": "vite build",   // npm run build → 打包
    "preview": "vite preview"
}
```

- `dependencies`：运行时需要的包（axios, vue, pinia, vue-router, naive-ui）
- `devDependencies`：仅开发时需要的包（vite, @vitejs/plugin-vue）——部署后不安装

### node_modules/

前端版 `E:\Python\Lib\site-packages`。`npm install` 后，包的代码放在这里。不只你装的 4 个包——这些包自己又依赖了其他包，整棵树被 npm 自动展开。此目录不提交 Git（`.gitignore` 已拦截）。

### index.html — 一切的起点

浏览器访问 `localhost:5173` 时，Vite 返回这个文件：

```html
<body>
    <div id="app"></div>                                        ← 空壳
    <script type="module" src="/src/main.js"></script>          ← 加载入口
</body>
```

你的整个聊天页面、登录页、导航栏——全是 Vue 在浏览器里动态塞进那个空 `<div id="app">` 的。HTML 本身只有十几行。

**专业术语**：SPA（Single Page Application，单页应用）——整个网站只有一个 HTML 文件，页面切换不刷新浏览器，由 JS 在同一个空壳里替换内容。

## 二、Vite

### 双重身份

| 身份 | 干什么 | 类比 |
|------|--------|------|
| **开发服务器** | `npm run dev` → `http://localhost:5173`，支持热更新 | Werkzeug 开发服务器（`app.run()`） |
| **构建工具** | `npm run build` → 编译/打包/压缩成 `dist/` 目录 | ❌ Werkzeug 没有这层 |

### 热更新（Hot Module Replacement, HMR）

你改 `.vue` 文件保存后，浏览器瞬间看到变化——不需要手动刷新。Vite 检测文件变化 → 重新编译变化部分 → 通过 WebSocket 通知浏览器局部替换该组件。

Werkzeug 的 `debug=True` 也有文件监控器，但它只监控 `.py` 文件且需要整个进程重启。Vite 的更新粒度更细——只替换改过的那一个组件。

### 构建（Build）

你写完 Vue 项目后，`.vue` 文件、`node_modules` 里的数百个包、ES6+ 新语法——浏览器不能直接消化。`npm run build` 做三件事：

1. **编译**：`.vue` 文件拆成 HTML / JS / CSS
2. **打包**：几十个零散文件合并成几个大文件（减少网络请求）
3. **压缩**：去掉空格、缩短变量名（减少文件体积）

产物是 `dist/` 目录下的纯静态文件。

**类比**：C 语言的 `gcc -c`（编译） + `ld`（链接） → `a.out`。共同原理——把人类可读的源文件通过编译→链接变成目标环境可直接消费的格式。区别：C 产物是 CPU 指令序列，Vite 产物是浏览器 JS 引擎可读的脚本。

### 为什么叫 Vite（法语"快"）

旧工具（Webpack）启动时要把整个项目先编译一遍——项目越大越慢。Vite 利用浏览器原生 ES Module 能力，**只编译当前访问页面用到的文件**。项目规模多大，启动时间几乎恒定。

## 三、WebSocket 与热更新的关系

### HTTP 的局限

HTTP 是单行道——服务器只能响应，不能主动发起：

```
客户端 ──请求──►  服务器     ← 必须先请求，服务器才能响应
客户端 ◄──响应──  服务器     ← 服务器不能主动找你
```

没有 WebSocket 时，Vite 改了文件想告诉浏览器——但服务器不能主动 push 通知。只能靠浏览器**轮询**：每隔 500ms 问一次"代码改了吗？"→ 99% 的请求浪费掉。

### WebSocket 的解决

在第一次 HTTP 握手后，协议从 HTTP **升级**为 WebSocket。同一条 TCP 连接，通信模型从"一问一答"变成**全双工双向**：

```
HTTP 请求 → 服务器回复 "101 Switching Protocols"（升级确认）
→ 同一根 TCP 管道，现在双方都能随时发消息
```

- Vite 用 WebSocket 做热更新（服务器主动通知浏览器"组件改了"）
- 你的聊天接口用 SSE（单向流），不是 WebSocket——聊天场景不需要服务器主动推消息
- **Socket 这个词**：WebSocket = 浏览器版的 socket。你去年写的 `socket_server.accept()` 拿 conn，浏览器用 `new WebSocket('ws://...')` 拿连接对象——同一个概念不同语言

## 四、代理（Proxy）

### 问题

```
前端地址：localhost:5173（Vite dev server）
后端地址：localhost:5000（Flask）
```

浏览器的**同源策略**：端口不同 → 判定跨域 → 禁止请求。`CORS(app)` 虽然能解决，但开发阶段有更简单的方式。

### 代理配置

```js
// vite.config.js
server: {
    proxy: {
        '/api': 'http://localhost:5000'
    }
}
```

### 代理做了什么

```
浏览器 ── /api/chat ──► Vite (5173)   ← 浏览器只跟 5173 说话
                            │
                            │ Vite 收到后，自己转发
                            ▼
                        Flask (5000)   ← Flask 收到的请求来自 Vite，不是浏览器
                            │
                            │ 返回结果
                            ▼
浏览器 ◄── 响应 ──────── Vite (5173)   ← Vite 把结果还给浏览器
```

**本质**：Vite = 中转站。浏览器以为在跟 5173 一个人对话，Flask 以为请求是 Vite 发的。两边都不知道对方的存在——跨域问题不触发。

### 代理的本质

Python 等价实现：

```python
@app.route('/<path:path>')
def proxy(path):
    if path.startswith('api/'):
        flask_response = requests.request(
            method=request.method,
            url=f'http://localhost:5000/{path}',
            headers=dict(request.headers),
            data=request.get_data()
        )
        return flask_response.content
```

`requests.request()` 内部做的事就是你去年写的裸 socket 客户端：`socket()` → `connect()` → `send(HTTP报文)` → `recv()` 收响应 → `close()`。

### 生产环境

`npm run build` 后前端变成 `dist/` 下的静态文件，部署到 Vercel/Netlify。这时没有 Vite dev server 了，代理不存在。跨域靠 `CORS(app)`（后端 Flask-CORS 加的响应头）。

### 代理的三类用途

| 用途 | 例子 |
|------|------|
| **绕过同源策略** | Vite dev server 代理 → Flask |
| **负载均衡** | Nginx 代理，把 1000 个请求分摊到 5 台后端服务器 |
| **安全隔离** | 反向代理暴露 443 端口给公网，内部服务器只监听内网，公网碰不到后端 IP |

### 进程与端口

两个进程不能占用同一端口——操作系统规定一个端口同一时刻只能被一个进程占用。Vite 占 5173，Flask 占 5000，这是物理限制，不是配置问题。代理让它们"看起来"同一个端口。

## 五、HTTP 协议 vs 裸 TCP

### 裸 TCP 能通信吗

能。你去年写的代码：

```python
conn.recv(1024)                # 拿一串字节
conn.send(msg.encode('utf-8')) # 回一串字节
```

这就是通信——没有 HTTP，纯 TCP 字节流。

### 为什么需要 HTTP

裸 TCP 的问题：**通信双方没有约定字节是什么意思。**

```
客户端发：b'POST /api/chat{"message":"hello"}token=abc123'
        ↑ 方法还是路径？请求体从哪开始？token 在哪？
```

你自己写的客户端和服务端，你知道字节什么意思——因为两端都是你写的。

但实际场景里，浏览器是谷歌写的，Flask 是另一个人写的，DeepSeek 是第三个人写的。它们之间不认识，唯一能互通的是一套**事先约定的字节排列规则**。HTTP 就是这套规则：

```
POST /api/chat HTTP/1.1          ← 第 1 行：方法 + 路径 + 协议版本
Authorization: Bearer abc123      ← 从第 2 行起：键: 值，一行一个头
Content-Type: application/json    ←
                                  ← 空行：下面是请求体
{"message": "hello"}              ← 请求体
```

有了这个格式，任何人写的程序按这个规则拼字节，任何服务器按这个规则拆字节，就能互相理解。

### 协议的本质

**协议不是物理限制，是人为约定的通信纪律。** TCP 管子是双向的（物理上两边都能发），HTTP 选了一问一答的回合制，WebSocket 选了双向随时发。同一个 TCP，不同规矩。

### 协议就是中间约定层

| 协议 | 谁和谁之间的约定 | 没它时 |
|------|----------------|--------|
| **HTTP** | 浏览器 ↔ 服务器 | 你的裸 TCP——换个人写的客户端就用不了 |
| **WSGI** | Python Web 服务器 ↔ Web 应用 | Flask 只能绑在 Werkzeug 一个服务器上 |
| **ORM** | Python 代码 ↔ 数据库 | 手写 SQL 字符串，换数据库重写全部 |

**共同模式**：在一对通信双方之间插入一层中间约定。往上的人只跟约定打交道，往下的人也跟约定打交道。往上和往下互不认识。

## 六、CORS（跨域资源共享）

浏览器的安全机制——**同源策略**。`localhost:5173`（前端）和 `localhost:5000`（后端）虽然在同一台机器上，但**端口不同**，浏览器判定跨域，默认禁止前端 JS 请求后端。

Flask-CORS 做的事：在后端每个 HTTP 响应头部自动加上 `Access-Control-Allow-Origin`，告诉浏览器"这个跨域请求我允许了"。

**开发阶段**：代理已经解决了端口问题（浏览器只跟 5173 通信），`CORS(app)` 用不上。  
**生产环境**：前端 Vercel、后端 Railway，浏览器直接跨域请求 → `CORS(app)` 真正发挥作用。

## 七、vite.config.js 逐行解析

```js
import { defineConfig } from 'vite'          // ①
import vue from '@vitejs/plugin-vue'          // ②

export default defineConfig({                 // ③
  plugins: [vue()],                           // ④
  server: {                                   // ⑤
    proxy: {
      '/api': 'http://localhost:5000'
    }
  }
})
```

### ① `import { defineConfig } from 'vite'`

Python 等价：`from vite import defineConfig`。

`defineConfig` 是一个函数，接收配置对象，原样返回。它的全部价值是让 VS Code 知道"这个对象的形状是什么"，在你敲 `server` 后自动弹出 `proxy` 选项。不写也能跑，但写配置像摸黑填表。

### ② `import vue from '@vitejs/plugin-vue'`

Python 等价：`from vitejs_plugin_vue import vue`。

Vite 原生只认识 `.js` 文件，不认识 `.vue` 文件。这个插件告诉 Vite：遇到 `.vue` 文件时，把里面三块（HTML 模板、JS 逻辑、CSS 样式）拆开，各自编译成浏览器能用的格式。不加此插件 → 所有 `.vue` 文件都是废纸。

### ③ `export default defineConfig({ ... })`

Python 等价：

```python
# vite.config.py
config = defineConfig({...})
# 其他文件里：from vite.config import config
```

`export default` = 这个文件对外暴露的默认值。Vite 启动时读 `vite.config.js`，拿到的东西就是 `defineConfig({...})` 的返回值。

### ④ `plugins: [vue()]`

`vue()` 调用插件，返回插件实例。`plugins: [vue()]` = "启用 Vue 插件"。以后加其他 Vite 插件，往数组里追加就行。

### ⑤ `server: { proxy: { ... } }`

`server` 控制 Vite dev server 的行为，`proxy` 定义代理规则。`'/api': 'http://localhost:5000'` = 路径以 `/api` 开头的请求，转发到 5000 端口。不以 `/api` 开头的（如 `/src/main.js`）Vite 自己处理。

## 八、JavaScript 模块语法速查

| JavaScript | Python 等价 | 含义 |
|---|---|---|
| `import { X } from 'y'` | `from y import X` | 具名导入 |
| `import X from 'y'` | `import X from y`（默认导出） | 默认导入 |
| `export default X` | 模块的"默认出口" | 别人 `import X from ...` 拿到的就是这个 |
| `export const X = ...` | 模块的普通导出 | 别人 `import { X } from ...` 拿 |

## 九、关键配置文件的作用总结

| 文件 | 作用 | 后端对应 |
|------|------|---------|
| `package.json` | 项目身份证 + 依赖清单 + 脚本定义 | `requirements.txt` |
| `vite.config.js` | Vite 配置（插件、代理、构建选项） | `config.py`（部分） |
| `index.html` | 浏览器入口，唯一的 HTML 文件 | ❌ 无对应 |
| `.gitignore` | 忽略 `node_modules/`、`dist/` 等 | 同一个 `.gitignore` |
