## 十四、建议的挖掘顺序

按**在你项目里最可能先遇到的问题**来排：

1. **SQLAlchemy session 和事务** — 你已经在写 add/commit，下一个 bug 大概率出现在"commit 失败怎么办"
2. **Flask 错误处理** — 你已经踩过 `None.strip()` 的崩溃，下一次会想知道 Flask 怎么抓住它
3. **CORS 预检** — 你部署到 Vercel + Railway 后第一个前端请求可能触发 OPTIONS
4. **JSON 序列化** — 你已经遇到过 `datetime` 不能序列化的错误
5. **Axios 拦截器** — token 自动注入、401 自动跳登录——前端每个请求都经过它
6. **SPA 路由原理** — 你的前端基石
7. **SSE 底层** — 和你的 chat.py 生成器一一对应
8. **SQL 注入** — ORM 替你防了，但你下次手写 SQL 时才知道这个防线在哪
9. **日志** — 你部署后第一个 500 错误没有堆栈可看时
10. **限流** — 你部署后被某个爬虫刷爆 DeepSeek 费用时
11. **数据库迁移** — 你第一次在已有用户数据的数据库上改模型结构时

其余 V8、Vue 编译器、浏览器渲染——随时可以回来拆，不会影响你继续写页面。
