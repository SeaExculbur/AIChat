## 二、已提到但没拆到底的

以下概念在对话或文档中提到过，但没追到源码/实现层：

### 2.1 CORS — Flask-CORS 到底做了什么

**你目前知道的**：`CORS(app)` 在响应头加 `Access-Control-Allow-Origin`，浏览器凭这个头放行跨域请求。

**没拆到的**：
- [ ] `CORS(app)` 内部怎么注册到 Flask 的？用了 `after_request` 钩子还是中间件？
- [ ] 为什么开发环境用 Vite 代理、生产环境用 CORS？两者的适用边界在哪？
- [ ] CORS 预检请求（Preflight）：`OPTIONS` 请求的触发条件、浏览器什么情况会先发 OPTIONS
- [ ] `Access-Control-Allow-*` 系列头部（Credentials、Methods、Headers）的完整规则
- [ ] 为什么简单请求（GET/POST 不带自定义头）不触发预检——浏览器怎么判断"简单" vs "非简单"
- [ ] **整个请求体不加头部在浏览器侧被直接发送，然后被服务器拒绝——这种场景下请求体已经泄露了吗？**

### 2.2 JSON 序列化 — `jsonify` 底层怎么把 Python 对象变成 JSON 字符串

**你目前知道的**：`jsonify(dict)` → JSON 字符串。Flask 内部用 Python 的 `json.dumps`。

**没拆到的**：
- [ ] `json.dumps` 怎么把 datetime 变成字符串（默认会报错——`isoformat` 是后来你手动加的）
- [ ] `jsonify` 如何自动设置 `Content-Type: application/json`
- [ ] `datetime.isoformat()` 返回的字符串格式由谁规定（ISO 8601——是谁定的、为什么）
- [ ] JSON 的字符串/数字/布尔/null 五种类型在 Python ↔ JavaScript 两边有细微差异吗

### 2.3 JWT — 签名算法 HS256 的具体步骤

**你目前知道的**：`create_access_token()` 签发了 JWT。签名 = Payload + JWT_SECRET_KEY → SHA-256 HMAC。

**没拆到的**：
- [ ] HMAC-SHA256 是什么：`HMAC(key, msg)` 和 `SHA256(msg)` 是一回事吗？不是——HMAC 防长度扩展攻击
- [ ] JWT 签名用的 HMAC 和 Git commit hash 用的 SHA-1 有什么区别
- [ ] `identity` 参数为什么接受字符串比接受整数更稳定——token 的 sub 字段是什么格式
- [ ] Token 过期时间 `exp` 怎么被嵌入 Payload——`create_access_token` 内部默认定时

### 2.4 密码哈希 — pbkdf2:sha256 是什么

**你目前知道的**：`generate_password_hash()` → 不可逆乱码。`check_password_hash()` 做同样的哈希后比对。

**没拆到的**：
- [ ] `pbkdf2:sha256:600000$...` 这串乱码的结构——`$` 是分隔符，拆开是什么含义
- [ ] 盐值（salt）是什么——为什么同样的密码两次哈希产生不同的乱码
- [ ] PBKDF2 和 SHA-256 的关系——PBKDF2 内部调用 SHA-256 多次（600000 次迭代）
- [ ] 600000 这个数字对应什么——迭代次数，每次迭代运行一次 SHA-256

### 2.5 SQLAlchemy — Query 对象和 session 管理

**你目前知道的**：`User.query.filter_by().first()` 翻译成 SQL。`db.session.add()` + `commit()` 写入数据库。

**没拆到的**：
- [ ] `db.session` 是什么——不是 Flask session，是 SQLAlchemy 的 Unit of Work 模式
- [ ] `commit()` 内部：怎么生成 SQL、怎么发送给 SQLite、怎么处理外键约束顺序
- [ ] `db.session.rollback()`——你项目里没用到，什么时候需要
- [ ] 连接池——SQLAlchemy 怎么维护到 SQLite 的连接、连接什么时候创建和销毁
- [ ] 事务（Transaction）——`commit()` 之前的所有操作是原子性的吗？SQLite 的隔离级别是什么

### 2.6 Flask 错误处理

**你目前知道的**：curl 返回 400/401/409/500 → 前端显示错误信息。

**没拆到的**：
- [ ] 你的代码崩了（比如 `None.strip()`）→ Flask 怎么抓住这个异常的、怎么变成 500 响应
- [ ] `debug=True` 时的浏览器交互式调试器——怎么实现的（Werkzeug DebuggedApplication）
- [ ] 生产环境 `debug=False` 时 500 错误返回什么——用户看不到堆栈只有 "Internal Server Error"
- [ ] Flask 的自定义错误处理：`@app.errorhandler(404)` ——你项目里目前没有

### 2.7 WSGI 中间件

**你目前知道的**：WSGI 是 Web 服务器和 Python 应用之间的标准插头。

**没拆到的**：
- [ ] 中间件（Middleware）是什么——在 `app(environ, start_response)` 外面再包一层函数
- [ ] WSGI 中间件链：请求进来时顺序经过 N 层中间件，响应出去时逆序回去
- [ ] 和装饰器/AppContext 的相似性——都是"不修改原件，在外面包一层"

### 2.8 部署相关

**你目前知道的**：开发用 Werkzeug，生产用 Gunicorn + Nginx。Nginx 做反向代理。

**没拆到的**：
- [ ] Gunicorn 的多进程模型（prefork）——每个进程一个独立 Python 解释器
- [ ] Gunicorn worker 数量怎么定——2*CPU核数+1 的经验公式从哪来
- [ ] Nginx 的反向代理——和 Vite 代理是同一个原理吗？是
- [ ] 负载均衡——多个 Gunicorn worker 之间怎么分配请求？Nginx 按什么策略
- [ ] 反向代理除了负载均衡外还有什么用途（安全隔离、静态文件服务、SSL 终结）

## 四、建议的挖掘顺序

不是按序号。按**在你项目里最可能先遇到的问题**来排：

1. **SQLAlchemy session 和事务** — 你已经在写 add/commit，下一个 bug 大概率出现在"commit 失败怎么办"
2. **Flask 错误处理** — 你已经踩过 `None.strip()` 的崩溃，下一次会想知道 Flask 怎么抓住它
3. **CORS 预检** — 你部署到 Vercel + Railway 后第一个前端请求可能触发 OPTIONS
4. **JSON 序列化** — 你已经遇到过 `datetime` 不能序列化的错误，下一次可能是别的类型
5. **SQL 注入** — ORM 替你防了，但你下次手写 SQL 时才知道这个防线在哪
6. **日志** — 你部署后第一个 500 错误没有堆栈可看时
7. **限流** — 你部署后被某个爬虫刷爆 DeepSeek 费用时
8. **数据库迁移** — 你第一次在已有用户数据的数据库上改模型结构时

## 五、和前端的关系

前端 `待拆解的底层逻辑清单.md` 里列了 60+ 项——Vue 编译器、V8 JIT、浏览器渲染管线——大部分不影响你写前端页面。建议优先拆解以下几条对工程能力立刻有提升的：

- [ ] SPA 路由原理 — `vue-router` 怎么让 URL 变了不刷新页面
- [ ] Axios 拦截器 — token 自动注入、401 自动跳登录
- [ ] SSE 底层 — 和你的 chat.py 生成器一一对应
- [ ] WebSocket vs SSE — 聊天场景为什么选 SSE 更合适

其余 V8、Vue 编译器、浏览器渲染——随时可以回来拆，不会影响你继续写页面。
