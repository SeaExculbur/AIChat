# AI 聊天网站 — 开发到上线流程

## 前置知识：前后端分离怎么通信

```
┌──────────────────────────┐         HTTP / JSON          ┌──────────────────────────┐
│    前端 (浏览器)          │ ◄──────────────────────────► │    后端 (服务器)           │
│                          │                              │                          │
│  只管"长什么样"           │  POST /api/chat              │  只管"数据怎么来"          │
│  不存数据、不碰 AI        │  { "message": "你好" }        │  处理业务逻辑              │
│                          │                              │  调 DeepSeek API           │
│  Vue 3 + Naive UI        │  { "reply": "你好！" }        │  读写数据库                │
│                          │  或 SSE 流式数据              │  Flask + SQLAlchemy       │
└──────────────────────────┘                              └──────────────────────────┘
```

- 前端 = 浏览器里跑的网页，只是展示界面
- 后端 = 服务器上跑的 Python 程序，真正干活的
- 两者通过 **HTTP 请求 + JSON 数据** 通信
- JSON 是前后端都能读懂的"通用语"——Python 用 `json.dumps/loads`，JS 用 `JSON.stringify/parse`

### 一个请求的完整生命周期

```
用户在输入框打字 → 点发送
  → 前端 JS 把消息打包成 JSON {message: "你好"}
  → Axios 发 POST 请求到 http://localhost:5000/api/chat
  → Flask 接收到请求 → 你的路由函数执行
  → 调用 DeepSeek API → 拿到 AI 回复
  → 把回复打包成 JSON 返回
  → 前端收到响应 → 把回复显示在聊天框里
```

### 0.3 Git 分支策略（简化版 Git Flow）

```
main          ← 生产环境代码，只从 dev 合并，不直接提交
  └── dev     ← 开发主分支，日常开发在这里
       └── feature/xxx   ← 每个功能拉一个分支
```

**实际操作：**

```bash
# 首次初始化后
git checkout -b dev          # 创建并切换到 dev 分支
git add .
git commit -m "chore: 初始化项目结构"

# 开发新功能时
git checkout dev
git checkout -b feature/chat-api    # 从 dev 拉功能分支
# ... 写代码 ...
git add .
git commit -m "feat: 实现聊天流式接口"
git checkout dev
git merge feature/chat-api          # 合并回 dev
git branch -d feature/chat-api      # 删除功能分支
```

### 0.4 Commit 规范（Conventional Commits）

```
feat:     新功能     feat: 添加用户注册接口
fix:      修 bug    fix: 修复流式响应中断问题
chore:    杂务      chore: 更新 Flask 到 3.0
docs:     文档      docs: 补充 API 文档
refactor: 重构      refactor: 抽取 JWT 验证为装饰器
test:     测试      test: 为聊天接口添加单元测试
```

每次 commit 只做一件事，message 用英文祈使句。

## 第 1 阶段：本地开发

### 1.1 后端开发（你熟悉的领域）

开发顺序——**先让后端每个接口都能用 curl/Postman 测通，再让前端对接**：

```
1. 创建 Flask 骨架
   ├── backend/app.py          # Flask 应用入口
   ├── backend/config.py       # 配置（数据库地址、Secret Key 等）
   └── backend/requirements.txt

2. 定义数据库模型 (models.py)
   ├── User 表：id, username, password_hash, created_at
   └── ChatHistory 表：id, user_id, role, content, created_at

3. 用户认证模块 (auth.py)
   ├── POST /api/auth/register   → 注册
   ├── POST /api/auth/login      → 返回 JWT token
   └── 用 curl 测试

4. 聊天接口 (chat.py)
   ├── POST /api/chat            → 先返回完整回复
   ├── 改造为 SSE 流式           → 打字机效果
   └── 用 curl 测试

5. JWT 鉴权装饰器
   ├── 所有 /api/* 接口加上 @jwt_required()
   └── 测试无 token 时返回 401

6. 跨域配置 (Flask-CORS)
   └── 允许前端开发服务器的跨域请求
```

### 1.2 前端开发（新领域，但可模仿）

```
1. 用 Vite 创建 Vue 3 项目
   npm create vite@latest frontend -- --template vue
   cd frontend && npm install

2. 安装依赖
   npm install axios naive-ui pinia vue-router

3. 页面搭建
   ├── src/views/Login.vue      # 登录页
   ├── src/views/Register.vue   # 注册页
   └── src/views/Chat.vue       # 聊天页（核心）

4. 前端怎么调后端
   ├── src/api/request.js       # Axios 封装（baseURL、拦截器）
   └── 发请求 → 拿数据 → 显示在页面上

5. 路由配置 (src/router/index.js)
   └── 未登录 → 重定向到登录页（路由守卫）

6. 状态管理 (src/store/)
   └── Pinia 存用户 token、当前对话列表
```

### 1.3 本地联调

```bash
# 终端 1：启动后端
cd backend
E:/Python/python.exe app.py          # 默认跑在 5000 端口

# 终端 2：启动前端
cd frontend
npm run dev                           # 默认跑在 5173 端口
```

前端 `vite.config.js` 配置代理，把 `/api` 请求转发到后端 5000 端口，避免跨域问题：

```js
export default defineConfig({
  server: {
    proxy: { '/api': 'http://localhost:5000' }
  }
})
```

### 2.1 测试金字塔

```
         ┌─────┐
         │ E2E │  ← 模拟真实用户操作（本阶段可选）

每个接口至少写一个测试：

        'username': 'test', 'password': '123456'
    })
    assert response.status_code == 201
    assert 'access_token' in response.json
```

## 第 4 阶段：部署上线

### 4.1 部署架构

```
用户浏览器
    │
    ▼
Vercel / Netlify（前端静态文件）
    │  API 请求
    ▼
Railway / Render（Flask 后端）
    │
    ├──► DeepSeek API
    └──► PostgreSQL / SQLite
```

### 4.2 后端部署（Railway）

1. 在 [railway.app](https://railway.app) 注册，关联 GitHub 仓库
2. Railway 自动检测 Python 项目，读取 `requirements.txt`
3. 在 Railway 面板设置环境变量：

```
DEEPSEEK_API_KEY=sk-xxxxx
JWT_SECRET_KEY=随机生成一串 32 位字符
FLASK_ENV=production
```

4. 部署命令：`gunicorn app:app`
5. 获得后端地址，如 `https://aichat-backend.up.railway.app`

### 4.3 前端部署（Vercel）

1. 在 [vercel.com](https://vercel.com) 注册，关联 GitHub 仓库
2. Vercel 自动检测 Vite 项目
3. 设置环境变量：

```
VITE_API_BASE_URL=https://aichat-backend.up.railway.app
```

4. 部署后获得前端地址，如 `https://aichat.vercel.app`

### 4.4 部署后验证

- [ ] 浏览器访问前端地址，页面正常加载
- [ ] 注册新用户 → 成功
- [ ] 登录 → 拿到 token，跳转聊天页
- [ ] 发一条消息 → AI 正常回复
- [ ] 刷新页面 → 历史记录还在
- [ ] 手机浏览器访问 → 界面适配正常

### 5.1 日常维护

- 查看 Railway 日志，排查异常

```
用户反馈 / 自己发现 bug
    → 从 dev 拉新分支
    → 改代码 + 写测试
    → 合并到 dev
    → 部署到线上
```

### 5.3 可选进阶

| 事项 | 说明 |
|------|------|
| Docker 容器化 | 一次构建，到处运行，解决环境差异 |
